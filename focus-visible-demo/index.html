:focus-visible shows the ring only when it matters

Every team has deleted a focus outline. A designer sees a ring around a button after a mouse click, calls it ugly, and someone writes outline: none. Then keyboard users get nothing at all. :focus-visible ends the trade-off: the ring appears when focus arrives by keyboard, and stays away when it arrives by mouse.

Click any control below with your mouse. No ring. Now press Tab until focus lands on one. Purple ring. Same controls, same stylesheet. The only difference is how focus got there. The readout at the top names each focus event as keyboard or mouse.

One honest caveat: Safari on macOS does not focus buttons on mouse click at all, so in Safari the left panel may show no ring on click either. That is Safari's own behavior, not the demo. The difference shows clearly on Tab, and in Chrome and Firefox on both click and Tab.

The fallback pattern

A browser that does not know :focus-visible ignores the rule, and the native outline still appears on :focus. Nothing breaks. The only way to break it is the old habit: :focus { outline: none } with no :focus-visible replacement. That removes the ring for everyone, including keyboard users, and fails WCAG 2.4.7. If you must support a browser without it, wrap the new rule in a feature query and keep the plain :focus ring as the fallback.

button:focus {
  outline: 3px solid #7c3aed;
}
@supports selector(:focus-visible) {
  button:focus {
    outline: none;
  }
  button:focus-visible {
    outline: 3px solid #7c3aed;
  }
}
Worth knowing: text inputs and textareas usually match :focus-visible even after a mouse click, because the browser expects you to type. That is the heuristic doing its job, not a bug.
Worth knowing: the browser decides what counts as keyboard focus. Tab and arrow keys count. A script calling .focus() usually does not, unless the last interaction was the keyboard.
