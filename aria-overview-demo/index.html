ARIA: An Overview

ARIA tells assistive technology what your interface is and what it is doing. This page explains the spec, its history, its five rules, and gives you four working patterns to try.

1.What it is

ARIA stands for Accessible Rich Internet Applications. It is a W3C specification that adds roles, states, and properties to HTML.

A role says what an element is, like tab or dialog. A state says what condition it is in, like pressed or expanded. A property adds a relationship or label, like aria-label or aria-controls.

Together they form a contract between the page and assistive technology. You describe the interface honestly, and screen readers announce it correctly. ARIA never changes how an element looks or behaves. It only changes how it is announced.

2.A short history

  • Sep 2006First public working draft. Ajax apps were leaving screen readers behind.
  • Jan 2011Candidate Recommendation.
  • Mar 20, 2014WAI-ARIA 1.0 becomes a W3C Recommendation.
  • Dec 2017ARIA 1.1, with new roles and digital publishing support.
  • 2023ARIA 1.2 becomes a W3C Recommendation.

3.The five rules of ARIA

  1. If native HTML does the job, use it. A real <button> beats <div role="button">.
  2. Do not change native semantics. A heading is a heading, so do not override it into a button.
  3. Every custom ARIA control must work with the keyboard.
  4. Never put role="presentation" or aria-hidden="true" on a focusable element.
  5. Every interactive element needs an accessible name.

The tabs

The tab pattern needs role="tablist", role="tab", and role="tabpanel", plus aria-selected on the active tab. Arrow keys move between tabs, Home and End jump to the ends, and only the active tab is in the Tab order.

Rule one of ARIA: if native HTML does the job, use it. A <button> already has a role, a name, and keyboard support. ARIA is for the things HTML cannot say.

A role answers the question "what is this?" A tab, a dialog, a switch. Get the role right and the screen reader picks the right announcement pattern.

A state answers the question "what condition is it in?" Pressed, expanded, selected, checked. States change as the user interacts, and the announcements follow.
