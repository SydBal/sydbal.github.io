light-dark() picks the color for both themes, in one declaration.

Every themed color used to live in two places: a custom property on :root for the light value, then the same property again inside a prefers-color-scheme media query. light-dark() collapses the pair. First value for light mode, second for dark, resolved by the color-scheme in effect. This page is themed with it. Flip the toggle below and watch every color on the page change with a single property flip.

What just happened

One property changed: color-scheme on :root. That is the whole toggle. The light-dark() calls do not know or care whether the scheme came from your operating system or from a button.

A toggle built this way cannot drift out of sync with the stylesheet, because there is only one switch and it lives in CSS.

The one line you cannot skip

light-dark() reads the element's used color-scheme, not your operating system setting directly. Without color-scheme: light dark set somewhere above it, every light-dark() call quietly returns its light value forever, even in dark mode. That is the single most common reason the function looks broken.

Old way, new way

The old way works everywhere, and it is twice the code for every color. The new way is one declaration per color.

/* Old way: every color declared twice */
:root {
  --surface: #ffffff;
  --ink: #17171c;
}
@media (prefers-color-scheme: dark) {
  :root {
    --surface: #18181e;
    --ink: #f1f0f5;
  }
}
/* New way: one declaration per color */
:root {
  color-scheme: light dark;
  --surface: light-dark(#ffffff, #18181e);
  --ink: light-dark(#17171c, #f1f0f5);
}

light-dark() only helps with color values. Layout, spacing, and anything else that differs between themes still belongs in a media query or a class.

Fallback for older browsers

Declare the light color first, then light-dark() right after it. A browser that does not know the function ignores the second line and keeps the first. The page stays light themed instead of breaking.

.card {
  background: #ffffff;
  background: light-dark(#ffffff, #18181e);
}
That trick does not work inside a custom property. An unregistered custom property stores the light-dark() text and resolves it at the use site, so a plain declaration first is not a real fallback there. Use the @supports pattern this page uses, or put light-dark() directly in the declaration.
