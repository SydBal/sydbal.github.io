The inert attribute

One HTML attribute that makes a whole subtree unfocusable, unclickable, and invisible to assistive technology. It is the missing half of every hand-rolled modal dialog.

What it does

Set inert on an element and the browser treats that element and everything inside it as if it isn't there for interaction: no tab stops, no click events, removed from the accessibility tree. The content still renders — it just can't be reached.

The classic use case is a modal. When your dialog opens, the page behind it should go inert. When the dialog closes, remove it. That's the whole pattern:

// opening your custom modal
dialog.classList.add("open");
document.querySelector("main").inert = true;

// closing it
dialog.classList.remove("open");
document.querySelector("main").inert = false;

What to notice

Without inert: tabbing walks straight past the modal into the nav links, the text field, and the buttons behind it. A keyboard user can get lost behind the overlay; a screen-reader user never knew the background was "behind" anything at all. The red entries in the log are focus escaping the dialog.

With inert: the background leaves the tab order entirely and drops out of the accessibility tree. One attribute, no focus-trap bookkeeping for the background — though pairing it with a small trap (or the native <dialog> element, which does this for you) is still the gold standard.

Browser support is broad: all modern browsers since ~2022. And it composes — inert subtrees can nest, and removing the attribute restores everything exactly as it was.
