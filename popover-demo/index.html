popover is the menu, tooltip, and panel with no JavaScript

Every popover used to need the same pile of script: open it, close it when you click outside, close it on Escape, fight the z-index to keep it on top, and return focus to the button that opened it. Now the browser does all of that. One attribute on the panel, one attribute on the button, and nothing else. Try all three examples below.

Checking this browser…

1. A menu

Tap the button. The menu opens in the top layer, above everything on the page, with no z-index anywhere. Click outside it, or press Escape, and it closes. Focus goes back to the button.

2. A tooltip

Same trick, smaller panel. This one holds a short explanation instead of links. It is click-activated, like the menu, so it works the same way with a keyboard or a touch screen.

Light dismiss

Clicking or tapping anywhere outside the popover closes it. The browser handles it. No document click listener, no checking whether the click landed inside the panel.

3. A settings panel

A popover can hold a whole little form. This one has a checkbox and a save button. Saving closes the panel with popovertargetaction="hide" on the button itself, still no script.

The JavaScript it replaces

Before this, the same menu needed all of this, and every line of it was a place to get it wrong.

// the old way, for one menu
button.addEventListener('click', () => panel.classList.toggle('open'));
document.addEventListener('click', (e) => {
  if (!panel.contains(e.target) && e.target !== button) {
    panel.classList.remove('open');
  }
});
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') panel.classList.remove('open');
});
// plus z-index, plus focus return, plus stacking
// when two panels are open at once

The popover version has none of it. The browser owns the top layer, so two popovers stack in the order they opened and the newest one closes first. The toggle event still exists if you want to react when one opens or closes, but you do not need it to make the panel work.

The Close button in every popover above is there for exactly that reason, and Escape still works where a keyboard is attached.

The fallback pattern

A browser that does not know the popover attribute shows the panel content inline, in the normal flow of the page. Nothing breaks and nothing is hidden. That is a usable fallback for a menu or a settings panel, and if the content must stay hidden in old browsers, hide it behind a feature check instead.

if ('showPopover' in document.createElement('div')) {
  // the browser has the Popover API
}
Worth knowing: popover without a value means popover="auto". Auto popovers close on outside clicks and close each other. popover="manual" stays open until you close it in script, and it does not light-dismiss.
Worth knowing: a popover is not a modal. For a dialog that traps focus and blocks the page, use <dialog> with showModal() instead.
