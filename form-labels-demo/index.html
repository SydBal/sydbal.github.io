A placeholder is not a label

A placeholder looks like a label until you start typing. Then it vanishes, right when you might want to re-read it. And for a screen reader user, it often was never a label at all. Below is the same small sign-up form twice: once the way too many sites build it, once the fixed way. Tab through both, or press the button to fill them in, and watch what the screen reader hears.

1. The broken way: placeholder only

Three fields, no labels anywhere. The grey text inside each box is doing all the work, and it stops working the moment you type. Focus a field and read the line underneath it: that is the name the browser can offer a screen reader, and where it came from.

2. The fixed way: a real label on every field

Same three fields. Each one has a visible <label> tied to it with for and id. The placeholder is still there, but now it only shows an example value, which is all a placeholder is for. The label stays put while you type.

3. What the screen reader hears

Tab through both forms above. Every time a field gets focus, a line is added here, showing what a screen reader announces for it. The broken form leans on the placeholder, and some screen readers skip that entirely, so for those users the field is just "edit text". The fixed form announces the label every time.

The fix, in full

One label per field, connected with for and id. That is the whole fix, and it is about five minutes of work.

<!-- Before: the placeholder does all the work -->
<input type="email" placeholder="Email address">

<!-- After: the label names the field, the
     placeholder only shows an example -->
<label for="email">Email address</label>
<input type="email" id="email"
       placeholder="ada@example.com">
Why this is a real failure, not a nitpick. WCAG 2.2 calls it out at Level A, the strictest tier: 1.3.1 Info and Relationships (the label must be programmatically tied to the field), 3.3.2 Labels or Instructions (a label or instructions must be provided), and 4.1.2 Name, Role, Value (every control needs a name assistive tech can read). A placeholder-only field fails all three.
No room for a visible label? Keep the <label> in the markup and hide it with a 1-by-1px clip, never with display: none, which removes it from the accessibility tree. And if the field needs no visible text at all, like a search box next to a magnifier, aria-label="Search" gives it a name. But a visible label is almost always better: sighted users read it too, and it keeps the visible and announced names the same.
